A device is one piece of hardware in a product. NervesHub knows it by its identifier, which is usually its serial number. A device's identifier cannot be changed after the device is created.

Adding, editing and deleting devices need the **Manage** role or higher. See [Roles](/access/roles).

## How devices get into a product

A device can add itself the first time it connects, or you can add it ahead of time.

| The device connects with | Does it add itself? |
| --- | --- |
| The product's shared secret (`nhp_` key) | Yes. NervesHub creates it in that product. |
| A shared secret of its own (`nhd_` key) | No. The key belongs to a device that already exists. |
| A certificate signed by a registered CA with a just-in-time provisioning profile | Yes. NervesHub creates it in the profile's product. See [Just-in-time provisioning](/auth/just-in-time-provisioning). |
| A certificate signed by a registered CA without a profile | No. Add the device first. NervesHub then records the certificate on first connection. |
| A self-signed certificate | No. Add the device and upload the certificate. |

## Add a device

<Tabs>
  <Tab title="Web UI">
    <Steps>
      <Step title="Open the dialog">
        Open **Devices** in the product and click **Add device**.
      </Step>

      <Step title="Describe the device">
        Enter the **Identifier**. This is what the device sends when it connects. **Description** and **Tags** are optional.
      </Step>

      <Step title="Choose how it connects">
        Under **How it connects**, choose one of:

        - **The product's shared secret**. Nothing more to set up. Shown when shared secrets are on for the instance and the product has an active secret.
        - **A shared secret of its own**. NervesHub creates a key and secret and shows the secret once. Shown when shared secrets are on for the instance.
        - **Its certificate**. Upload the certificate as a PEM or DER file. You can skip the upload when one of your registered CA certificates signed it.
      </Step>

      <Step title="Add it">
        Click **Add device**. If you chose a secret of its own, copy the **Key** and **Secret** before you close the dialog.
      </Step>
    </Steps>
  </Tab>

  <Tab title="CLI">
    ```bash
    nh device create my-device-001 --tag production --description "Line 2 gateway"
    ```

    To create the device and its own shared secret in one step:

    ```bash
    nh device create my-device-001 --shared-secret
    ```

    The secret is printed once and cannot be fetched again. The server refuses the request, and creates no device, when shared secrets are off for the instance.
  </Tab>
</Tabs>

List devices or show one:

```bash
nh device list
nh device show my-device-001
```

To search and filter the list, see [Finding devices](/management/finding-devices).

### Add many devices from a Trust&Go manifest

`nh device import` creates a device, with its certificate, for every entry in a Microchip Trust&Go manifest. This is the only import format. It does not take CSV.

```bash
# Check the manifest without sending it
nh device import manifest.json --dry-run

# Import it, tagging every device
nh device import manifest.json --tag batch-7
```

NervesHub creates the devices in the background and posts a [product notification](/management/notifications) with how many it created and how many failed.

## Set tags

Tags decide which deployment group a device matches. See [Deployment groups](/setup/deployments#how-devices-join-a-group).

```bash
nh device update my-device-001 --tag main --tag qa
```

`--tag` sets the device's whole tag list. The flags that set device fields on `nh device create` and `nh device update` need NervesHub 2.5.3 or later.

You cannot put a device in a deployment group directly from the CLI or API. NervesHub assigns a device to a group whose version and tag conditions it matches when the device connects. A tag you set on a connected device is compared the next time it connects. In the web UI you can place a device in a group yourself. See [Put a device in a group by hand](/setup/deployments#put-a-device-in-a-group-by-hand).

In the web UI, edit tags on the device's **Settings** tab.

## Manage credentials

Open the device's **Settings** tab.

### Certificates

The **Certificates** card lists the certificates on file for the device, who signed each, and when it was last used. Click **Upload certificate** to add one as a PEM or DER file.

```bash
nh device certificates list my-device-001
nh device certificates upload my-device-001 cert.pem
nh device certificates delete my-device-001 <serial>
```

`nh device certificates generate` creates a key and certificate on your machine. See [Device certificates](/auth/device-certificates).

### Shared secrets

The **Shared secrets** card is shown when shared secrets are on for the instance. Click **Create secret** to issue a key for this device. The secret is shown once.

```bash
nh device shared-secrets list my-device-001
nh device shared-secrets create my-device-001
nh device shared-secrets delete my-device-001 <key>
```

`delete` deactivates the key. See [Shared secret](/auth/shared-secret).

## Act on a device

```bash
nh device reboot my-device-001
nh device reconnect my-device-001
nh device console my-device-001
nh device clear-penalty my-device-001
```

`console` opens the device's IEx console and needs `remote_iex: true` in the firmware. See [Remote console](/management/remote-console). `clear-penalty` clears the device's penalty box. See [Rollout controls](/deployments/rollout-controls).

Show the log lines a device has sent, or follow new ones:

```bash
nh device logs my-device-001
nh device logs my-device-001 --follow
```

Logs need the logging [extension](/extensions/overview). See [Logging](/extensions/logging).

## Delete and restore a device

On the device's **Settings** tab, click **Delete device…**. NervesHub disconnects the device, removes it from its deployment group and deletes its certificates. A deleted device cannot connect: its certificates and its own shared secret keys stop authenticating, and a product key cannot create a new device under its identifier.

```bash
nh device delete my-device-001
```

To bring a deleted device back, click **Restore device** on its **Settings** tab. A restored device is matched to a deployment group again the next time it connects. Its certificates were deleted with it, so upload them again unless a registered CA signed them.

To remove a deleted device for good, click **Delete permanently…**.
