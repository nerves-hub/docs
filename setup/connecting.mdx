NervesHubLink opens a WebSocket connection to NervesHub when the device boots and keeps it open. NervesHub uses that connection to tell the device about firmware updates, run the [remote console](/management/remote-console), and receive [extension](/extensions/overview) data. For how the device authenticates, see the pages under device authentication, starting with [Shared secret](/auth/shared-secret).

## Set the host

Set `host` to the host name devices connect to. This is the device endpoint, which is usually a different host from the web UI.

```elixir
# config/target.exs
config :nerves_hub_link,
  host: "devices.nervescloud.com"
```

`host` takes a host name, or a full URL when you need a port:

```elixir
config :nerves_hub_link,
  host: "wss://your.nerveshub.host:4001"
```

When `host` has no scheme, NervesHubLink uses `wss://`.

If the TLS server name differs from the host you connect to, set `sni`:

```elixir
config :nerves_hub_link,
  host: "10.0.0.5",
  sni: "your.nerveshub.host"
```

<Warning>
  `device_api_host`, `device_api_port` and `device_api_sni` are deprecated. NervesHubLink logs a warning when you set them. Use `host` and `sni`.
</Warning>

## Trust the server certificate

NervesHubLink verifies the server certificate on every connection. It chooses the CA certificates to trust in this order:

1. `cacerts` in the `ssl` option.
2. The module set as `ca_store`. It must export `ca_certs/0` and return a list of DER-encoded certificates.
3. The [CAStore](https://hex.pm/packages/castore) package, if it is in your project.
4. The CA certificates installed on the device.

If your instance uses a certificate from a private CA, set the certificates yourself:

```elixir
config :nerves_hub_link, ca_store: MyApp.CAStore
```

Or pass DER-encoded certificates directly:

```elixir
config :nerves_hub_link,
  host: "your.nerveshub.host",
  ssl: [cacerts: my_der_list]
```

Any Erlang `:ssl` client option can go in `ssl`. TLS 1.3, session resumption, HTTP proxies and Msgpack are covered in [Transport](/connection/transport).

## Devices configured with the web host

A NervesHub instance can redirect devices that connect to the web host to the device host. `nerves_hub_link` 2.10.0 and later follow the redirect. NervesHub also posts a [product notification](/management/notifications) that names the device and the host it should use. The redirect is an instance setting. See [Feature prerequisites](/hosting/feature-prerequisites#other-defaults).

## Reconnection

NervesHubLink reconnects on its own when the connection drops. The delay starts at one second and doubles up to 60 seconds, with up to 50% added as jitter. To change it, or to control when the connection starts, see [Connection lifecycle](/connection/lifecycle).

## Turn the connection off

```elixir
# config/test.exs
config :nerves_hub_link, connect: false
```

With `connect: false`, the application starts no connection processes.

## Build the configuration at runtime

When credentials are not known at build time, implement the `NervesHubLink.Configurator` behaviour. `build/1` receives the configuration read from the application environment and returns the configuration to use.

```elixir
defmodule MyApp.Configurator do
  @behaviour NervesHubLink.Configurator

  @impl NervesHubLink.Configurator
  def build(config) do
    ssl = [certfile: "/root/ssl/cert.pem", keyfile: "/root/ssl/key.pem"]
    %{config | ssl: ssl}
  end
end
```

```elixir
config :nerves_hub_link, configurator: MyApp.Configurator
```

Setting `configurator` replaces the built-in choice between [NervesKey](/auth/nerveskey), [TPM](/auth/tpm) and shared secret. See [Connection lifecycle](/connection/lifecycle).
