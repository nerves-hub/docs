title: "Add NervesHubLink to a project"

`nerves_hub_link` is the client library that connects a Nerves device to NervesHub. You add the dependency, point it at your NervesHub host, and choose how the device proves who it is. The device appears in your product the first time it connects.

## Requirements

- A Nerves project. `nerves_hub_link` 2.13.0 and later need Elixir 1.15 or later.
- A product in NervesHub. See [Products](/setup/products).
- Each device needs a unique serial number. With a shared secret, NervesHub identifies the device by the serial number its firmware reports. With a certificate, NervesHub identifies the device by the certificate's common name, so issue each certificate with the device's serial number as its common name.

<Steps>
  <Step title="Add the dependency">
    Add `nerves_hub_link` to the target dependencies in `mix.exs`:

    ```elixir
    defp deps do
      [
        # ... existing deps ...
        {:nerves_hub_link, "~> 2.14"}
      ]
    end
    ```

    Then fetch it:

    ```bash
    mix deps.get
    ```

    `nerves_hub_link` is an OTP application and starts with your firmware. You do not need to add it to a supervision tree. To start it yourself, see [Connection lifecycle](/connection/lifecycle).
  </Step>

  <Step title="Choose how the device authenticates">
    NervesHubLink picks a configurator in this order:

    1. The module you set as `configurator` in the `:nerves_hub_link` config.
    2. `NervesHubLink.Configurator.NervesKey`, if the `nerves_key` library is in your project.
    3. `NervesHubLink.Configurator.TPM`, if the `tpm` library is in your project.
    4. `NervesHubLink.Configurator.SharedSecret`.

    | Method | What the device holds | Page |
    | --- | --- | --- |
    | Shared secret | A key and secret, for the product or for one device | [Shared secret](/auth/shared-secret) |
    | Certificate and key on the filesystem | An X.509 certificate and private key | [Device certificates](/auth/device-certificates) |
    | NervesKey | A certificate and key in a NervesKey secure element | [NervesKey](/auth/nerveskey) |
    | TPM | A certificate and key in a TPM | [TPM](/auth/tpm) |

    Shared secrets are the quickest way to connect a first device. They only work when the NervesHub instance has them turned on. See [Feature prerequisites](/hosting/feature-prerequisites#shared-secret-authentication).
  </Step>

  <Step title="Configure the connection">
    Add the configuration for your method to `config/target.exs`. Replace the host with your NervesHub device host.

    <Tabs>
      <Tab title="Shared secret">
        Create a shared secret in **Product settings** and copy its key and secret. See [Shared secret](/auth/shared-secret).

        ```elixir
        # config/target.exs
        config :nerves_hub_link,
          host: "devices.nervescloud.com",
          shared_secret: [
            product_key: System.fetch_env!("NERVES_HUB_PRODUCT_KEY"),
            product_secret: System.fetch_env!("NERVES_HUB_PRODUCT_SECRET")
          ]
        ```

        `System.fetch_env!/1` runs when you build the firmware. Set both variables in the shell or CI job that runs `mix firmware`.
      </Tab>

      <Tab title="Certificate and key files">
        ```elixir
        # config/target.exs
        config :nerves_hub_link,
          host: "devices.nervescloud.com",
          configurator: NervesHubLink.Configurator.LocalCertKey
        ```

        By default the configurator reads `/data/nerves-hub/cert.pem` and `/data/nerves-hub/key.pem`. See [Device certificates](/auth/device-certificates).
      </Tab>

      <Tab title="NervesKey">
        ```elixir
        # mix.exs
        {:nerves_key, "~> 1.2"}
        ```

        ```elixir
        # config/target.exs
        config :nerves_hub_link,
          host: "devices.nervescloud.com"
        ```

        See [NervesKey](/auth/nerveskey).
      </Tab>

      <Tab title="TPM">
        ```elixir
        # mix.exs
        {:tpm, "~> 0.2.0"}
        ```

        ```elixir
        # config/target.exs
        config :nerves_hub_link,
          host: "devices.nervescloud.com"
        ```

        See [TPM](/auth/tpm).
      </Tab>
    </Tabs>

    <Tip>
      To stop NervesHubLink from connecting while you run tests, set `connect: false`:

      ```elixir
      # config/test.exs
      config :nerves_hub_link, connect: false
      ```
    </Tip>
  </Step>

  <Step title="Set up firmware signing">
    From `nerves_hub_link` 2.13.0, a device refuses firmware it cannot signature-check. A device with no `fwup_public_keys` configured asks NervesHub for your organization's signing keys when it connects. If it has none configured and receives none, it stops taking updates.

    Register a signing key before you upload firmware. See [Firmware signing](/concepts/firmware-signing).
  </Step>

  <Step title="Build, burn, and check the connection">
    ```bash
    export MIX_TARGET=rpi4   # replace with your target
    mix firmware
    mix firmware.burn
    ```

    Boot the device and open **Devices** in your product. A connected device shows as **Online**.

    If the device does not appear, check:

    - The device has a network connection and can reach the host. NervesHubLink checks that the network is available before its first connection attempt.
    - With a shared secret, the key and secret match an active secret in **Product settings**, and the device clock is correct. NervesHub accepts a signature for 90 seconds.
    - With a certificate, the signing CA is registered and the device exists or the CA has a [just-in-time provisioning](/auth/just-in-time-provisioning) profile. See [Device certificates](/auth/device-certificates).
  </Step>
</Steps>
