A product groups the devices, firmware, [archives](/updates/archives), deployment groups and [support scripts](/management/support-scripts) for one kind of device. Every device belongs to one product. An organization can have many products, for example one for a gateway and one for a sensor.

Creating a product, changing its settings and deleting it need the **Manage** role or higher. See [Roles](/access/roles).

## Create a product

<Tabs>
  <Tab title="Web UI">
    <Steps>
      <Step title="Open your organization">
        Open the organization's **Products** page.
      </Step>

      <Step title="Create the product">
        Click **New product**. Enter a **Name**, choose the device extensions, and click **Create Product**.

        In an organization with no products, the page shows a **Create your first product** form instead. Enter the **Product name** and click **Create product**. Every device extension starts on.
      </Step>
    </Steps>

    On the **New product** form every device extension starts checked.
  </Tab>

  <Tab title="CLI">
    ```bash
    nh product create my_app
    ```

    A product created with the CLI or the API starts with every device extension off. Turn on the ones you need in **Product settings**.
  </Tab>
</Tabs>

<Warning>
  A product's name cannot be changed. Devices and the CLI refer to the product by name.
</Warning>

List products or show one, with its settings:

```bash
nh product list
nh product show my_app
```

## Set the default organization and product for the CLI

Most `nh` commands need an organization and a product. Save them once:

```bash
nh config set org my-org
nh config set product my_app
```

You can also set `NERVES_HUB_ORG` and `NERVES_HUB_PRODUCT`, or pass `--org` and `--product` on a command. A flag overrides an environment variable, which overrides the saved setting. See [CLI configuration](/cli/configuration).

## Product settings

Open **Product settings** in the product sidebar. It has three tabs: **General**, **Device health** and **API keys**.

The **General** tab holds:

| Card | What it controls |
| --- | --- |
| **General** | The product name and its organization. Read-only. |
| **Firmware** | **Require unique firmware versions**, and which firmware formats other than fwup the product accepts. See [Firmware](/setup/firmware). |
| **Shared secrets** | The product's shared secret keys. See [Shared secret](/auth/shared-secret). |
| **Device extensions** | Which extensions devices in this product may use. |
| **Device-managed updates** | Whether devices may choose their own update mode. See [Device-managed updates](/updates/device-managed-updates). |

Health profiles are on the **Device health** tab. See [Health monitoring](/management/health-monitoring). [Product API keys](/api/authentication#product-api-keys) are on the **API keys** tab. See [CI/CD](/outbound/ci-cd).

<Note>
  Product API keys are on the main branch and are not in a tagged release as of NervesHub 2.5.4.
</Note>

Some settings can also be changed with `nh product update`. Only the flags you pass are sent:

```bash
nh product update my_app --require-unique-firmware-version=false
```

### Device extensions

An extension must be on for the product before any of its devices can use it. Each device also has its own setting per extension, which is on by default. Turning an extension off for the product turns it off on every device.

| Extension | Description shown in the UI |
| --- | --- |
| **Health** | Metrics, firmware metadata and alarms, reported together. |
| **Metrics** | The device's metrics on their own, without Health's metadata and alarms. |
| **Geo** | Location from GeoIP, or a source you set up on the device, for the map. |
| **Logging** | Stream device logs to the Logs tab. |
| **Error reports** | Crashes and exceptions, grouped on the Errors page. |
| **Local shell** | A shell on the device's OS, beside the IEx console. |
| **Alarms** | Alarms sent as they're raised and cleared, not on Health's schedule. |
| **Network identity** | Identities the device holds on networks like NetBird or iroh. |

The device firmware must also include the extension. See [Extensions overview](/extensions/overview).

### What is not a product setting

Firmware signing keys and certificate authorities belong to the organization, not the product. Find them on the organization's **Signing keys** and **Certificates** pages. See [Firmware signing](/concepts/firmware-signing) and [Device certificates](/auth/device-certificates).

## Delete a product

In the web UI, open **Product settings** and click **Delete product**. The button is only enabled when the product has no devices. You confirm by typing the product name. The product's firmware, archives, deployment groups, support scripts and settings go with it.

```bash
nh product delete my_app
```

The CLI asks you to confirm. Pass `--yes` to skip the prompt.

<Warning>
  Deleting a product cannot be undone from the UI or the CLI. The CLI and API do not check whether the product still has devices. NervesHub refuses every device whose product has been deleted, however it authenticates.
</Warning>
