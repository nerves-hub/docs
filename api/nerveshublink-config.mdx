`nerves_hub_link` is the Elixir library that runs on your Nerves device and manages the NervesHub WebSocket connection, firmware update lifecycle, health reporting, and remote console access. You configure it through standard Elixir application config, and it handles all protocol details — including reconnection, progress reporting, and fwup invocation — automatically.

<Note>
  Place all `nerves_hub_link` configuration in `config/target.exs`, not `config/config.exs`. Target config is only compiled into your firmware and keeps device-specific settings out of your host development environment.
</Note>

## Add the Dependency

Add `nerves_hub_link` to your `mix.exs` dependencies:

```elixir
# mix.exs
def deps do
  [
    {:nerves_hub_link, "~> 2.7"},
    # ... other deps
  ]
end
```

Run `mix deps.get` to fetch the library, then add configuration to `config/target.exs`.

## Connection Settings

Set the NervesHub device API hostname and control whether the library connects on startup. For NervesCloud, the device hostname is `devices.nervescloud.com`.

```elixir
# config/target.exs
config :nerves_hub_link,
  host: "devices.nervescloud.com",
  connect: true
```

| Key       | Type    | Default                     | Description                                                                             |
| --------- | ------- | --------------------------- | --------------------------------------------------------------------------------------- |
| `host`    | string  | `"devices.nervescloud.com"` | Device API hostname                                                                     |
| `connect` | boolean | `true`                      | Set to `false` to disable automatic connection on startup (useful in test or CI builds) |

<Tip>
  Set `connect: false` in `config/host.exs` or your CI environment to prevent your application from trying to reach NervesHub during local development and testing.
</Tip>

## Authentication

NervesHub supports three authentication modes. Choose one based on your device's capabilities and security requirements.

<Tabs>
  <Tab title="Shared Secret">
    Shared secret authentication uses a `product_key` and `product_secret` to identify devices. It is the quickest way to get started and is well-suited for development, prototyping, or devices without hardware security modules.

    ```elixir
    # config/target.exs
    config :nerves_hub_link,
      shared_secret: [
        product_key: System.get_env("NERVES_HUB_PRODUCT_KEY"),
        product_secret: System.get_env("NERVES_HUB_PRODUCT_SECRET")
      ]
    ```

    Retrieve your `product_key` and `product_secret` from the NervesHub web console under **Settings → Shared Secrets** for your product.

    <Tip>
      Use `System.get_env/1` to read credentials from environment variables at runtime rather than hardcoding them in your config files. This keeps secrets out of version control and makes it easy to rotate credentials.
    </Tip>
  </Tab>

  <Tab title="Device Certificates (mTLS)">
    Certificate-based authentication uses X.509 device certificates presented during the mTLS handshake. This is the recommended approach for production deployments because each device has a unique cryptographic identity.

    ```elixir
    # config/target.exs
    config :nerves_hub_link,
      ssl: [
        certfile: "/path/to/device_cert.pem",
        keyfile: "/path/to/device_key.pem"
      ]
    ```

    | Key        | Type   | Description                                         |
    | ---------- | ------ | --------------------------------------------------- |
    | `certfile` | string | Path to the device's X.509 certificate (PEM format) |
    | `keyfile`  | string | Path to the device's private key (PEM format)       |

    Certificate files are typically provisioned onto the device at manufacturing time and stored in a location that persists across firmware updates. See the [Device Certificates guide](/auth/device-certificates) for provisioning instructions.
  </Tab>

  <Tab title="NervesKey (Hardware)">
    NervesKey uses an ATECC508A or ATECC608A hardware security module to store the private key in tamper-resistant hardware. The private key never leaves the chip, making this the most secure option for production devices.

    ```elixir
    # config/target.exs
    config :nerves_hub_link,
      configurator: NervesKey.NervesHubLinkConfigurator
    ```

    Refer to the [NervesKey documentation](https://github.com/nerves-hub/nerves_key) for full provisioning and configuration details.
  </Tab>
</Tabs>

## Remote IEx Console

Enable the remote IEx console to allow operators to open an interactive Elixir shell on a connected device from the NervesHub web console.

```elixir
# config/target.exs
config :nerves_hub_link,
  remote_iex: true
```

| Key          | Type    | Default | Description                                                      |
| ------------ | ------- | ------- | ---------------------------------------------------------------- |
| `remote_iex` | boolean | `false` | Enable the remote IEx console over the `console` WebSocket topic |

<Warning>
  The remote IEx console gives full Elixir runtime access to your device. Only enable it where that level of access is appropriate, and ensure your NervesHub organization roles are configured correctly — opening a console requires the `manage` role.
</Warning>

## Firmware Signing Key Verification

NervesHub signs firmware with Ed25519 keys. Configure the public keys your device trusts so that `nerves_hub_link` can verify firmware signatures before applying an update.

```elixir
# config/target.exs
config :nerves_hub_link,
  fwup_public_keys: [
    "base64_encoded_public_key_here"
  ]
```

| Key                | Type            | Description                                                                                  |
| ------------------ | --------------- | -------------------------------------------------------------------------------------------- |
| `fwup_public_keys` | list of strings | Base64-encoded Ed25519 public keys; firmware must be signed by at least one key in this list |

You can list multiple keys to support key rotation without requiring a firmware update to distribute a new key. `nerves_hub_link` will accept firmware signed by any key in the list.

## Self-Hosted NervesHub

If you are running a self-hosted NervesHub instance, configure the device API hostname, SNI, and port to point to your server instead of NervesCloud.

```elixir
# config/target.exs
config :nerves_hub_link,
  device_api_host: "device.my-nerves-hub.org",
  device_api_sni: 'device.my-nerves-hub.org',
  device_api_port: 443
```

| Key               | Type     | Description                                                                |
| ----------------- | -------- | -------------------------------------------------------------------------- |
| `device_api_host` | string   | Hostname of your self-hosted NervesHub device API                          |
| `device_api_sni`  | charlist | TLS SNI hostname (note: this is an Elixir **charlist**, use single quotes) |
| `device_api_port` | integer  | TCP port for the device API (default: `443`)                               |

<Note>
  `device_api_sni` must be a charlist (single-quoted string in Elixir), not a binary string. This matches the format expected by Erlang's `:ssl` library.
</Note>

## Socket Options

Tune the underlying Phoenix Channels socket behaviour, including the JSON library and heartbeat interval.

```elixir
# config/target.exs
config :nerves_hub_link,
  socket: [
    json_library: Jason,
    heartbeat_interval: 45_000
  ]
```

| Key                  | Type    | Default  | Description                                             |
| -------------------- | ------- | -------- | ------------------------------------------------------- |
| `json_library`       | module  | `Jason`  | JSON encoder/decoder module to use for channel messages |
| `heartbeat_interval` | integer | `30_000` | Milliseconds between WebSocket heartbeat pings          |

## Custom Runtime Configurator

If your device reads configuration from the network, a local file, or a hardware provisioning partition at boot time, implement a custom `Configurator` module to provide settings dynamically at runtime rather than compile time.

```elixir
# config/target.exs
config :nerves_hub_link,
  configurator: MyApp.Configurator
```

Your configurator module receives the base configuration and returns a modified version:

```elixir
defmodule MyApp.Configurator do
  @behaviour NervesHubLink.Configurator

  @impl NervesHubLink.Configurator
  def build_config(config) do
    # Read credentials from a provisioning partition or KV store
    product_key = Nerves.Runtime.KV.get("nerves_hub_product_key")
    product_secret = Nerves.Runtime.KV.get("nerves_hub_product_secret")

    %{config |
      shared_secret: [
        product_key: product_key,
        product_secret: product_secret
      ]
    }
  end
end
```

## Custom Update Client

To control how your device responds to firmware update notifications — for example, to defer updates during critical operations or only apply updates during a maintenance window — implement a custom `Client` module.

```elixir
# config/target.exs
config :nerves_hub_link,
  client: MyApp.NervesHubLinkClient
```

See the [NervesHubLink Client Behaviour guide](/api/nerveshublink-client) for full implementation details and examples.

## Complete Example

A typical `config/target.exs` for a production NervesCloud device using shared secret authentication:

```elixir
# config/target.exs
import Config

config :nerves_hub_link,
  host: "devices.nervescloud.com",
  connect: true,
  remote_iex: true,
  shared_secret: [
    product_key: System.get_env("NERVES_HUB_PRODUCT_KEY"),
    product_secret: System.get_env("NERVES_HUB_PRODUCT_SECRET")
  ],
  fwup_public_keys: [
    System.get_env("NERVES_HUB_FWUP_PUBLIC_KEY")
  ],
  client: MyApp.NervesHubLinkClient,
  socket: [
    heartbeat_interval: 45_000
  ]
```
