NervesHub shows your fleet at three levels: every organization you belong to, one product, and one device. This page maps what each level shows and points to the pages that cover each part in depth.

## The home page

You land on the home page after you sign in. It shows, in order:

* What needs attention across your organizations: [releases](/deployments/releases) waiting for approval, unhealthy devices, and devices stuck in the [penalty box](/deployments/rollout-controls).
* Your pinned devices.
* Each organization's products.

Selecting a product opens its **Insights** page.

## A product

Every product page has a sidebar. Its header names the organization and product and counts the devices online. The links are **Insights**, **Devices**, **Deployment groups**, **Firmware**, **Archives**, **Support scripts**, **Errors**, **Notifications**, and **Product settings**.

Some links carry a status line. **Devices** shows how many devices are unhealthy, or failing that, how many have warnings. **Deployment groups** shows a release that is awaiting approval. **Notifications** shows a count.

<Note>
  A member whose custom role is limited to devices with certain tags sees only those devices. Pages built from all of a product's devices, such as **Insights** and **Notifications**, are closed to them. See [Roles](/access/roles).
</Note>

| Page | What it answers | More |
| --- | --- | --- |
| **Insights** | What the fleet is made of by connection, health and firmware version, and how that has moved | [Insights and history](/management/insights) |
| **Devices** | Which devices match a state, a filter or a query | [Finding devices](/management/finding-devices) |
| **Notifications** | What NervesHub noticed that nothing else would show you | [Product notifications](/management/notifications) |
| **Support scripts** | The scripts you can run on a device | [Support scripts](/management/support-scripts) |

<Note>
  The fleet dashboard from NervesHub 2.4 and earlier was removed in 2.5.0. **Insights** takes its place.
</Note>

## The devices list

**Devices** lists every device in the product. Tabs across the top slice the list by state:

| Tab | Devices it holds |
| --- | --- |
| **All** | Every device |
| **Online** | Connected now |
| **Needs attention** | Unhealthy, stopped taking updates after repeated failures, or not seen in 14 days |
| **Updating** | Installing an update now |
| **Offline** | Not connected now, including devices never seen |

**Needs attention** has its own reasons to narrow by: **Unhealthy**, **Update failing**, and **Not seen 14 d+**.

The table always shows the device. You choose which of the other columns show: **Health**, **Firmware**, **Platform**, **Deployment group**, **Connection**, and **Tags**.

Selecting a row opens a side panel with enough about the device to decide whether to open its page.

Searching, filtering, columns, bulk actions, and export are covered in [Finding devices](/management/finding-devices).

## The device page

Selecting a device's identifier opens its page. The header shows the device's connection, and has the **Identify**, **Reconnect**, **Reboot…**, and **Pin device** actions. Pinned devices show on your home page.

| Tab | What it shows | More |
| --- | --- | --- |
| **Details** | Health, firmware updates, support scripts, and general info | |
| **Health** | Health status, metric charts, and when the device was online | [Health monitoring](/management/health-monitoring) |
| **Firmware History** | Each firmware the device reported, and how each update sent to it ended | [Insights and history](/management/insights) |
| **Console** | A remote IEx console | [Remote console](/management/remote-console) |
| **System Shell** | A shell on the device | [Local shell](/extensions/local-shell) |
| **Logs** | Log lines the device sent | [Logging](/extensions/logging) |
| **Errors** | Errors the device reported | [Error reports](/extensions/error-reports) |
| **Activity** | The audit log for the device | [Audit log](/access/audit-log) |
| **Data History** | Every message that crossed the device's connection | [Insights and history](/management/insights) |
| **Settings** | The device's settings | [Devices](/setup/devices) |

## Connection status

A device is online while it holds a WebSocket connection to NervesHub. When the connection closes, NervesHub records when and why, and the device shows as offline with when it was last seen.

A device that has been added but has never connected shows as never connected.

A battery device that sleeps between reports can tell NervesHub so, and shows as asleep instead of offline. See [Devices that sleep](/management/sleeping-devices).

## What needs ClickHouse

Current state is always available: the devices list, the device page, what the fleet is made of on **Insights**, and the list of devices failing to update.

History needs ClickHouse on the NervesHub instance:

* The trend charts and the **Flapping** list on **Insights**
* The connection lane on a device's **Health** tab
* The **Update attempts** view on a device's **Firmware History** tab
* The **Data History**, **Logs**, and **Errors** tabs
* Metric history charts

See [Feature prerequisites](/hosting/feature-prerequisites#clickhouse).

## Inspect the fleet from the CLI

The commands below assume you have signed in and set a default organization and product. See [CLI configuration](/cli/configuration).

List the devices in the product:

```bash
nh device list
```

Narrow the list with `--filter key:value`. Repeat the flag to combine filters:

```bash
nh device list --filter connection:connected --filter tags:prod
```

A `tags` filter takes comma-separated tags. A device needs all of them, and each is matched as part of a tag, so `prod` matches `production`.

Show one device:

```bash
nh device show my-device-001
```

Every command accepts `-o json` (`--output json`) for machine-readable output:

```bash
nh device list --filter connection:not_seen -o json
```

`nh device list` also takes the search bar's query language with `--query`. See [Finding devices](/management/finding-devices).
