NervesHub is an open-source firmware update and device management platform. It was built for [Nerves](https://nerves-project.org/) devices and can also update other Linux and ESP32 devices. Devices hold a WebSocket connection to NervesHub. Over that connection NervesHub tells a device when firmware is available, and you get a remote console, [health](/management/health-monitoring) reports and other device data back.

## What NervesHub does

- **Signed firmware updates.** You sign firmware before you upload it. NervesHub checks the signature against the signing keys registered for your organization, and the device checks it again before applying the update. See [Firmware signing](/concepts/firmware-signing).
- **Controlled rollouts.** A deployment group targets devices by tag and version condition. You can limit how many devices update at once, stop a rollout when failures pass a threshold, and stage a [release](/deployments/releases) with a workflow. See [Deployment groups](/setup/deployments) and [Rollout controls](/deployments/rollout-controls).
- **Updates on the device's terms.** Your firmware decides when to apply an update, reports progress, and can defer or refuse. See [Applying updates](/updates/applying-updates).
- **Remote access.** Open an IEx console on a connected device, run [support scripts](/management/support-scripts), reboot it, or ask it to identify itself. See [Remote console](/management/remote-console).
- **Device data.** Extensions report health metrics and alarms, location, log lines, error reports and [network identities](/extensions/network-identity). See [Extensions](/extensions/overview).
- **Device authentication.** Devices authenticate with a shared secret or with an X.509 certificate, which can be held in a [NervesKey](/auth/nerveskey) or a [TPM](/auth/tpm). See [Shared secrets](/auth/shared-secret) and [Device certificates](/auth/device-certificates).
- **Integration.** An HTTP API, the `nh` CLI, webhooks, and [Slack](/outbound/slack), Microsoft Teams and Discord notifications. See [API overview](/api/overview) and [Webhooks](/outbound/webhooks).

Some features depend on how the instance is set up. See [Feature prerequisites](/hosting/feature-prerequisites).

## The parts

| Part | What it is |
| --- | --- |
| NervesHub | The server: web UI, HTTP API and the endpoint devices connect to. Source at [nerves-hub/nerves_hub_web](https://github.com/nerves-hub/nerves_hub_web). |
| NervesHubLink | The Elixir library you add to a Nerves project. It holds the connection and applies updates. See [NervesHubLink](/integrations/nerves-hub-link). |
| `nh` | The command-line tool for signing and uploading firmware and managing devices and deployment groups. See [CLI installation](/cli/installation). |
| Other device clients | Clients for Linux without Nerves, ESP-IDF and AtomVM. See [Integrations](/integrations/overview). |

[Architecture](/architecture) describes how they fit together.

## Where to run it

<CardGroup cols={2}>
  <Card title="NervesCloud" icon="cloud" href="https://manage.nervescloud.com">
    A hosted NervesHub. You manage devices at `manage.nervescloud.com`, and devices connect to `devices.nervescloud.com`.
  </Card>

  <Card title="Self-hosted" icon="server" href="https://github.com/nerves-hub/nerves_hub_web">
    Run NervesHub on your own infrastructure. It is a Phoenix application that needs PostgreSQL and somewhere to store firmware files: a local disk or S3-compatible object storage.
  </Card>
</CardGroup>

NervesHub, NervesHubLink and `nh` are open source. NervesHub is released under the [Apache License 2.0](https://github.com/nerves-hub/nerves_hub_web/blob/main/LICENSE).
