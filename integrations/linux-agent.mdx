[nerves-hub-link-agent](https://github.com/nerves-hub/nerves-hub-link-agent) is a NervesHub client for Linux systems that are not running Nerves. It is one Rust binary that runs beside your application. It does not write firmware itself: it runs the update tool your image already has, `fwup` or `rauc`.

The agent:

- reports which firmware the device is running
- receives updates and runs the update tool
- can ask your application whether to install an update and whether to reboot
- confirms a good boot so the bootloader releases its rollback
- runs support scripts
- answers health, geo, logging, [local shell](/extensions/local-shell) and [network identity](/extensions/network-identity) requests

<Warning>
  The agent has been exercised end to end against a NervesHub, and both update tools install, roll back and validate on a QEMU rig with a real bootloader. It has not yet run on production hardware.

  Client-certificate authentication and resumable downloads are not implemented. The agent refuses to start with a client-certificate config.
</Warning>

## Requirements

| What | Needed |
| --- | --- |
| Device | Linux. The agent reads `/proc` and `/sys` and shells out to the update tool. |
| Update tool | `fwup` or `rauc` in the image, already configured for A/B updates |
| Authentication | A [shared secret](/auth/shared-secret). The instance must have shared secrets enabled. See [feature prerequisites](/hosting/feature-prerequisites#shared-secret-authentication). |
| Firmware format | fwup works on any instance. RAUC must be enabled for the instance and the product. See [RAUC bundles](/updates/rauc). |
| Rust | 1.85 or later, to build |

## Build

```bash
cargo build --release
```

This builds `nerves-hub-link-agent` and `agent-ctl` in `target/release/`.

Update tools are cargo features. The default feature set is `sandbox` and `fwup`. A config file cannot select a tool that was not built in. Build a device binary with only the tool it has:

```bash
cargo build --release --no-default-features --features fwup
cargo build --release --no-default-features --features rauc
```

## Connect a device with the sandbox tool

Start with the `sandbox` update tool. It downloads firmware, verifies its SHA-256, writes it to a file and stops. It touches no block device or bootloader, and a reboot is only a log line.

<Steps>
  <Step title="Create a shared secret">
    Create a product shared secret in NervesHub. See [Shared secret authentication](/auth/shared-secret). You get a product key that starts with `nhp_` and a product secret.
  </Step>

  <Step title="Write a config file">
    ```toml agent.toml
    [server]
    host = "devices.nervescloud.com"
    # port = 443, tls = true and path = "/device-socket" are the defaults

    [identity]
    product_key = "nhp_..."
    product_secret = "..."
    identifier = { literal = "bench-01" }

    [update_tool]
    name = "sandbox"
    work_dir = "/tmp/nerves-hub-agent"
    initial_firmware = { uuid = "00000000-0000-0000-0000-000000000000", version = "0.1.0", product = "my_app", platform = "sandbox", architecture = "x86_64" }

    [ipc]
    socket = "/tmp/nerves-hub-agent.sock"
    ```

    For your own instance, set `host` to its device endpoint.

    `initial_firmware` is what the sandbox reports as the running firmware before anything is installed. Without it the device has no firmware for a [deployment group](/setup/deployments) to compare against.
  </Step>

  <Step title="Run the agent">
    ```bash
    ./target/release/nerves-hub-link-agent --config agent.toml
    ```

    The device appears in NervesHub under the identifier you configured.

    Set `RUST_LOG=nerves_hub_link_agent=debug` to log the URL it connects to and every frame in both directions.
  </Step>

  <Step title="Send it an update">
    Upload fwup firmware to the product and target the device from a deployment group. The sandbox downloads it into `work_dir`, and you can watch progress in NervesHub.
  </Step>
</Steps>

<Tip>
  The sandbox reports itself to NervesHub as `fwup`, and the startup log line reads `update tool fwup (sandboxed)`. It stands in for the fwup path, so test it with fwup firmware.
</Tip>

## Configuration

The agent reads one TOML file. It looks for the path in this order:

1. `--config <path>` (or `-c <path>`)
2. The `NERVES_HUB_AGENT_CONFIG` environment variable
3. `/etc/nerves-hub-link-agent.toml`

[`examples/agent.toml`](https://github.com/nerves-hub/nerves-hub-link-agent/blob/main/examples/agent.toml) in the repository lists every option with its default.

### Server

```toml
[server]
host = "devices.nervescloud.com"
port = 443
path = "/device-socket"
tls = true
# ca_certificate = "/etc/ssl/certs/my-ca.pem"   # default: the system trust store
heartbeat_interval_secs = 30
reconnect_backoff_secs = [1, 2, 5, 10, 30, 60]
```

`host` is a host name only, with no scheme or path. The other values shown are the defaults.

### Identity

```toml
[identity]
product_key = "nhp_..."
product_secret = "..."
identifier = { file = "/sys/firmware/devicetree/base/serial-number" }
```

The identifier comes from one of three sources:

| Form | Reads |
| --- | --- |
| `{ literal = "bench-01" }` | The value itself |
| `{ file = "/path" }` | The first line of a file |
| `{ command = "/usr/bin/read-serial" }` | The first line of a command's output, run once at startup |

<Warning>
  A product shared secret registers any identifier NervesHub has not seen before. A wrong identifier creates a second device without an error. A literal identifier in a shipped image makes every device the same device. An identifier stored in the root filesystem is lost at the first update, so read it from the hardware or from a data partition.
</Warning>

### fwup

```toml
[update_tool]
name = "fwup"
device = "/dev/mmcblk0"
allow_block_device = true
task = "upgrade"
binary = "/usr/bin/fwup"
public_key = "..."
confirm_command = "/usr/bin/fwup --apply --task validate --no-unmount -d /dev/mmcblk0 -i /usr/share/fwup/ops.fw --quiet"
metadata = { file = "/etc/nerves-hub/firmware.env" }
```

| Key | Default | Purpose |
| --- | --- | --- |
| `device` | required | The device fwup writes to |
| `allow_block_device` | `false` | Must be `true` for `device` to be a block device. The agent refuses to start otherwise. |
| `task` | `upgrade` | The fwup task to run |
| `binary` | `/usr/bin/fwup` | Path to fwup |
| `public_key` | none | The public key fwup verifies the archive against. Set it, so the device checks the bytes it received. |
| `extra_args` | `[]` | Extra arguments for fwup |
| `confirm_command` | none | Run when the firmware is marked valid. Required. The agent refuses to start without it. |
| `metadata` | `{ file = "/etc/nerves-hub/firmware.env" }` | Where the running firmware's metadata comes from, as `key=value` lines. Use `{ command = "fw_printenv" }` on a device with a U-Boot environment. |

The archive streams into fwup as it downloads. The agent reports its fwup version and NervesHub decides whether to send a [delta](/management/delta-updates), as it does for Nerves devices. See [`docs/fwup.md`](https://github.com/nerves-hub/nerves-hub-link-agent/blob/main/docs/fwup.md) for what the image must provide.

### RAUC

```toml
[update_tool]
name = "rauc"
binary = "/usr/bin/rauc"
stream_from_url = true
tls_no_verify = false
firmware_file = "/etc/nerves-hub/firmware"
```

| Key | Default | Purpose |
| --- | --- | --- |
| `binary` | `/usr/bin/rauc` | Path to rauc |
| `stream_from_url` | `true` | Hand `rauc install` the firmware URL. Staging the bundle to disk is not implemented. With `false` the agent refuses the install. |
| `tls_no_verify` | `false` | Pass `--tls-no-verify` to `rauc install` |
| `firmware_file` | `/etc/nerves-hub/firmware` | A file in the root filesystem that says which firmware the image is |

What the image must provide:

- **RAUC 1.9 or later.** The agent refuses to start with an older version.
- **The RAUC service.** `rauc install` is a D-Bus client of `rauc service`. The agent checks for the service at startup.
- **A `system.conf`** that describes the slots, names a real bootloader backend, and points at a keyring. RAUC verifies bundles against that keyring. The agent has no signature settings for RAUC.
- **Verity bundles.** Streaming requires them, and NervesHub refuses plain bundles.

The agent marks a boot good with `rauc status mark-good booted`.

**Identifying the running firmware.** The agent reads `firmware_file` first. It holds `key=value` lines for `uuid`, `version`, `product`, `platform` and `architecture`, written by your image build. Pair it with a `uuid` in the bundle manifest's `[meta.nerveshub]` section so that both sides name the same firmware. When the file is absent, the agent falls back to the bundle hash RAUC recorded for the booted slot. That hash exists only for slots RAUC installed, so a device flashed another way cannot report its firmware until its first RAUC update. See [RAUC bundles](/updates/rauc#the-firmware-uuid).

See [`docs/rauc.md`](https://github.com/nerves-hub/nerves-hub-link-agent/blob/main/docs/rauc.md) for the slot configuration and a QEMU rig.

### Update and reboot policy

```toml
[updates]
policy = "apply"        # or "ask"
ask_timeout_secs = 30
on_timeout = "apply"
on_no_controller = "apply"

[reboot]
policy = "immediate"    # or "ask" or "never"
command = "sudo reboot"
```

`policy = "apply"` installs whatever arrives. `policy = "ask"` asks your application first. Reboot policy is separate, so an application can accept a download and still defer the reboot.

The default reboot command is `sudo reboot`, because the agent is meant to run as an unprivileged user. That needs one sudoers rule:

```
agent ALL=(root) NOPASSWD: /sbin/reboot
```

### Talking to your application

```toml
[ipc]
socket = "/run/nerves-hub-link-agent.sock"
mode = 0o660
require_controller = false
```

Your application talks to the agent over a Unix socket with newline-delimited JSON. One connection can be the controller, which answers update and reboot questions. Other connections are observers. See [`docs/ipc.md`](https://github.com/nerves-hub/nerves-hub-link-agent/blob/main/docs/ipc.md).

`agent-ctl` is a small client for the same socket:

```bash
agent-ctl status        # connection, identity, firmware, whether validation is owed
agent-ctl mark-valid    # confirm the running firmware, releasing the rollback
agent-ctl reboot
agent-ctl watch         # stream events
```

## Extensions and support scripts

The agent implements five extensions. All are off by default in the agent's config. The product and the device must also have the extension enabled in NervesHub.

| Extension | Config table | Reports |
| --- | --- | --- |
| Health | `[extensions.health]` | Memory, CPU, load and temperature from `/proc` and `/sys` |
| Geo | `[extensions.geo]` | A GeoIP position, a fixed position, or the output of a command |
| Logging | `[extensions.logging]` | `journalctl --follow`, or the output of a command |
| Local shell | `[extensions.local_shell]` | A shell on a pty, `/bin/sh` by default |
| Network identity | `[extensions.network_identity]` | Keys from commands you configure |

Turn one on with `enabled = true` in its table:

```toml
[extensions.health]
enabled = true
```

<Warning>
  The local shell runs commands as the user the agent runs as, for anyone NervesHub allows to open it. Read [`docs/extensions.md`](https://github.com/nerves-hub/nerves-hub-link-agent/blob/main/docs/extensions.md) before you enable it.
</Warning>

Support scripts are on by default. On this agent a script runs as a shell script, with `bash` as the default interpreter and a 10 second timeout. Scripts belong to the product, so a script written in Elixir for Nerves devices does not run here. See [Support scripts](/management/support-scripts).

```toml
[scripts]
enabled = true
interpreter = "bash"
timeout_secs = 10
```
