[meta-nerveshub](https://github.com/nerves-hub/meta-nerveshub) is a Yocto layer with one recipe, `nerves-hub-link-agent`. It builds the [Linux agent](/integrations/linux-agent) and installs it with a systemd unit, a service user and a starter config file.

The layer does not build bundles or configure slots. That is the job of [meta-rauc](https://github.com/rauc/meta-rauc), or of your fwup configuration.

## Requirements

| What | Needed |
| --- | --- |
| Yocto release | The layer declares compatibility with `scarthgap`, `styhead`, `walnascar` and `whinlatter`. Its test script builds against `scarthgap`. |
| [meta-rust-bin](https://github.com/rust-embedded/meta-rust-bin) | Always. It supplies the Rust toolchain. |
| [meta-rauc](https://github.com/rauc/meta-rauc) | When the agent is built for RAUC, which is the default |
| [meta-fwup](https://github.com/fwup-home/meta-fwup) | When the agent is built for fwup |
| systemd | As the init manager |

The recipe uses meta-rust-bin's `cargo_bin` class, not poky's `cargo`, because the Rust that `scarthgap` and `walnascar` ship is older than the agent needs. meta-rust-bin packages prebuilt upstream toolchains, not ones your build compiled, which matters if you have reproducibility or audit requirements.

## Add the layer

<Steps>
  <Step title="Add the layers">
    For a RAUC image:

    ```bash
    bitbake-layers add-layer /path/to/meta-rauc
    bitbake-layers add-layer /path/to/meta-rust-bin
    bitbake-layers add-layer /path/to/meta-nerveshub
    ```

    meta-nerveshub declares a dependency on `core` only. A missing update tool layer is reported when the recipe is parsed, with a message naming the layer to add.
  </Step>

  <Step title="Configure the distro and image">
    ```bitbake
    IMAGE_INSTALL:append = " nerves-hub-link-agent"
    DISTRO_FEATURES:append = " rauc"
    INIT_MANAGER = "systemd"
    ```

    `rauc` in `DISTRO_FEATURES` is meta-rauc's requirement. Leave it out for an fwup image.
  </Step>

  <Step title="Replace the starter config">
    The recipe installs `/etc/nerves-hub-link-agent.toml` with placeholder credentials. Override it from your own layer. See [Configure the agent](#configure-the-agent).
  </Step>
</Steps>

<Warning>
  Without systemd in `DISTRO_FEATURES`, the recipe skips installing the unit. The package still builds and installs the binary, but nothing starts it.
</Warning>

## Choose the update tool

The recipe maps `PACKAGECONFIG` to the agent's cargo features. The default is `rauc`.

| `PACKAGECONFIG` | Builds | Adds to the image | Layer needed |
| --- | --- | --- | --- |
| `rauc` (default) | The RAUC update tool | `rauc` | meta-rauc |
| `fwup` | The fwup update tool | `fwup` | meta-fwup |
| `sandbox` | The sandbox tool, which writes to a file only | Nothing | None |

To build for fwup, set this in your configuration or a `.bbappend`:

```bitbake
PACKAGECONFIG:pn-nerves-hub-link-agent = "fwup"
```

Extensions are not build options. They are turned on in the agent's config file.

## What the recipe installs

| Item | Detail |
| --- | --- |
| Binaries | The agent, started as `/usr/bin/nerves-hub-link-agent` |
| Config | `/etc/nerves-hub-link-agent.toml`, marked as a config file of the package |
| Service | `nerves-hub-link-agent.service`, enabled, running as user `agent` and group `agent` |
| User | System user and group `agent` |
| Directories | systemd creates `/run/nerves-hub-link-agent` and `/var/lib/nerves-hub-link-agent` for the service |

The unit also gives the service the `systemd-journal` group, which the logging extension needs to read the journal.

## Configure the agent

The starter config connects to `devices.nervescloud.com` with the RAUC update tool. It contains placeholders that you must replace:

```toml
[identity]
product_key = "nhp_REPLACE_ME"
product_secret = "REPLACE_ME"
identifier = { file = "/data/nerves-hub/identifier" }
```

It also sets the IPC socket to `/run/nerves-hub-link-agent/agent.sock` and the reboot command to `reboot`.

Ship your own file from your product's layer, so that the config is versioned with the image. See [Linux agent](/integrations/linux-agent#configuration) for every section. The agent's [`docs/deploying.md`](https://github.com/nerves-hub/nerves-hub-link-agent/blob/main/docs/deploying.md) covers the device identifier, file permissions for the service user, and the sudoers rule for an unprivileged reboot.

For a RAUC image, the device also needs the RAUC service running and a `system.conf` with its slots and keyring. See the agent's [`docs/rauc.md`](https://github.com/nerves-hub/nerves-hub-link-agent/blob/main/docs/rauc.md), and [RAUC bundles](/updates/rauc) for what NervesHub needs in the bundle manifest.

## Update the crate list

Yocto fetches sources before it builds, so the recipe lists every crate the agent depends on. After the agent's `Cargo.lock` changes, regenerate the list:

```bash
bitbake -c update_crates nerves-hub-link-agent
```

This rewrites `nerves-hub-link-agent-crates.inc`.

The recipe pins the agent to a git revision. A new agent version is a new recipe file.
