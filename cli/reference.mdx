This page lists every `nh` command. Run any command with `--help` for its full description and examples.

All commands accept the [global flags](/cli/configuration#global-flags): `--uri`, `--token`, `--org`, `--product`, `--data-dir`, `--non-interactive` and `-o`/`--output`. Commands that work on a product need an organization and a product, from flags, environment variables or saved settings.

Commands that delete or deactivate something ask for confirmation first. Pass `-y` or `--yes` to skip the prompt.

## `nh user`

Sign in and inspect the current user.

```bash
nh user login     # sign in on the web and enter the code nh shows
nh user auth      # sign in with email and password
nh user whoami    # show the signed-in user
nh user logout    # remove the saved API token
```

| Command | Flag | Description |
| --- | --- | --- |
| `login` | `--no-browser` | Do not open the sign-in URL in a browser. |
| `auth` | `--email <email>` | Account email. Skips the email prompt. |

`nh user auth` is refused for an account with [two-factor authentication](/access/two-factor) on. Use `nh user login`. See [Configuration](/cli/configuration#sign-in).

## `nh org`

Manage organizations and their members.

```bash
nh org list                       # organizations you belong to
nh org show [name]                # one organization
nh org members [name]             # members of an organization (alias: users)
nh org member <email>             # one member
nh org invite <email> <role>      # invite a user (alias: add-member)
nh org set-role <email> <role>    # change a member's role
nh org remove-member <email>      # remove a member
```

`<role>` is `admin`, `manage` or `view`. The API cannot assign custom roles, so assign those in the web interface. Setting a built-in role on a member who holds a custom role replaces the custom role. `nh org members` shows a custom role by its name, marked `(custom)`.

Inviting members, changing roles and removing members need the **Admin** role. See [Roles](/access/roles).

## `nh product`

Manage products.

```bash
nh product list             # products in the organization
nh product show <name>      # one product and its settings
nh product create <name>
nh product update <name>    # change settings
nh product delete <name>
```

`nh product update` sends only the flags you pass. A product cannot be renamed.

| Flag | Description |
| --- | --- |
| `--allow-tool <format>` | Accept this firmware format as well. Repeatable, or comma-separated. |
| `--disallow-tool <format>` | Stop accepting this firmware format. Repeatable, or comma-separated. |
| `--tools <list>` | Set the whole list of accepted formats. Cannot be combined with the two flags above. |
| `--allow-unsigned-esp-idf` | Accept ESP-IDF images with no Secure Boot v2 signature. |
| `--allow-unsigned-atomvm` | Accept AtomVM packbeams with no signature. |
| `--require-unique-firmware-version` | Reject firmware whose version already exists for the product. |
| `--default-managed-updates-allowed` | Let devices created in this product manage their own updates. |

The formats are `fwup`, `esp-idf`, `atomvm` and `rauc`. `fwup` is always kept. The yes/no flags take `=true` or `=false`, and the flag on its own means true.

```bash
nh product update my_app --allow-tool esp-idf --allow-unsigned-esp-idf
nh product update my_app --require-unique-firmware-version=false
```

A format other than `fwup` must also be enabled on the instance. See [Feature prerequisites](/hosting/feature-prerequisites#firmware-formats).

## `nh device`

Manage the devices in a product.

```bash
nh device list
nh device show <identifier>
nh device create <identifier>
nh device update <identifier>
nh device delete <identifier>
nh device import <manifest.json>
```

### `nh device list`

| Flag | Description |
| --- | --- |
| `--page <n>` | Page number. |
| `--page-size <n>` | Devices per page. |
| `--sort <column>` | Sort by `identifier`, `connection_established_at`, `connection_last_seen_at` or `tags`. Add `:desc` to reverse, for example `identifier:desc`. |
| `--filter <key>:<value>` | Narrow the results. Repeatable. Run `nh device list --help` for the keys and values. |
| `-q`, `--query <expression>` | An advanced query, in the language the web interface's device search uses. Needs NervesHub 2.5.0 or later. |

```bash
nh device list --filter connection:connected --filter tags:prod
nh device list --query 'metric:cpu_temp > 70'
nh device list --query 'health_status != "healthy" or alarm_status = "with"'
```

See [Finding devices](/management/finding-devices) for the query language.

### `nh device create` and `nh device update`

`update` changes only the fields you pass.

| Flag | Description |
| --- | --- |
| `--description <text>` | Device description. `""` clears it. |
| `--tag <tag>` | Device tag. Repeatable. |
| `--update-mode <mode>` | `off`, `automatic` or `device_managed`. See [Device-managed updates](/updates/device-managed-updates). |
| `--managed-updates-allowed` | Whether the device may put itself into `device_managed` mode. |
| `--connecting-code <code>` | Elixir code the device runs each time it connects. `""` clears it. Needs NervesHub 2.5.3 or later. |
| `--shared-secret` | `create` only. Also create the device's own shared secret and print it. It is shown only once. |

The API cannot set a device's [deployment group](/setup/deployments). NervesHub assigns a device to a group whose version and tag conditions it matches when the device connects. To place a device in a group yourself, use the web UI. See [Put a device in a group by hand](/setup/deployments#put-a-device-in-a-group-by-hand).

### `nh device import`

Create devices, with their certificates, from a Microchip Trust&Go manifest. Pass `-` to read the manifest from standard input.

| Flag | Description |
| --- | --- |
| `--tag <tag>` | Tag for every imported device. Repeatable, or comma-separated. |
| `--dry-run` | Check the manifest locally and send nothing. |

`nh` checks every entry first and sends nothing if any has a problem. NervesHub creates the devices in the background and reports the result on the product's notifications page.

### Device actions

```bash
nh device upgrade <identifier> <firmware-uuid>   # send a firmware to the device
nh device move <identifier> --to-product <name>  # move to another product
nh device reboot <identifier>
nh device reconnect <identifier>
nh device clear-penalty <identifier>             # take the device out of the penalty box
```

`nh device move` takes `--to-product` (required) and `--to-org` (defaults to the current organization).

### Remote access

```bash
nh device console <identifier>        # remote IEx console
nh device shell <identifier>          # local shell on the device
nh device iroh-console <identifier>   # remote IEx console over a peer-to-peer iroh connection
```

All three need an interactive terminal. `console` and `shell` need a user access token, not a product API key. See [Remote console](/management/remote-console) and [Local shell](/extensions/local-shell).

| Command | Flag | Description |
| --- | --- | --- |
| `iroh-console` | `--auth <response>` | Response to the device's authentication challenge. |
| `iroh-console` | `--instance <name>` | Which iroh endpoint of the device to connect to. Default `iroh_console`. |

Press Ctrl-] to detach from an iroh console.

### `nh device logs`

Show the log lines a device has sent. See [Logging](/extensions/logging).

| Flag | Description |
| --- | --- |
| `--level <levels>` | Only lines at these levels. Repeatable, or comma-separated. |
| `--search <text>` | Only lines whose message contains this text. Case-insensitive, matched literally. |
| `--since <time>` | Only lines at or after this time. ISO 8601, or an offset such as `2h`. |
| `--before <time>` | Only lines before this time. |
| `--limit <n>` | Maximum lines to return. Default 100. |
| `--order <order>` | `desc` for newest first (default), or `asc`. |
| `--meta` | Append the metadata the device attached to each line. |
| `-f`, `--follow` | Print new lines as they arrive, by polling, until interrupted. |
| `--interval <duration>` | How often `--follow` polls. |

### `nh device metrics`

Show the metric readings a device has reported, grouped by metric name. See [Metrics and alarms](/extensions/metrics-and-alarms).

| Flag | Description |
| --- | --- |
| `--key <names>` | Only these metrics. Repeatable, or comma-separated. |
| `--since <time>` | Only reports at or after this time. ISO 8601, or an offset such as `2h`. |
| `--before <time>` | Only reports before this time. |
| `--limit <n>` | Maximum reports to return. Default 100. |
| `--order <order>` | `desc` for newest first (default), or `asc`. |
| `--list-keys` | List the metric names in the fetched reports instead of their readings. |
| `-f`, `--follow` | Print new readings as they arrive, by polling, until interrupted. |
| `--interval <duration>` | How often `--follow` polls. |

### Run code and scripts

```bash
nh device run-code <identifier> <code>              # run Elixir code on the device
nh device scripts <identifier>                      # list the support scripts the device can run
nh device run-script <identifier> <name-or-id>      # run a support script and print its output
```

| Command | Flag | Description |
| --- | --- | --- |
| `scripts` | `--page <n>`, `--page-size <n>` | Page through the list. |
| `run-script` | `--timeout <duration>` | How long the server waits for the device's output, for example `2m`. The server default is 30 seconds. |

For `scripts` and `run-script`, `--org` and `--product` are optional. Set both or neither. When set, the device must belong to that product.

See [Support scripts](/management/support-scripts).

### `nh device network-identities`

List the keys a device reports holding on other networks. Alias: `identities`. See [Network identity](/extensions/network-identity).

| Flag | Description |
| --- | --- |
| `--service <name>` | Only identities for this protocol, for example `iroh`. |
| `--instance <name>` | Only this endpoint of the protocol. |

### `nh device certificates`

Manage a device's certificates. Alias: `certs`.

```bash
nh device certificates list <identifier>
nh device certificates show <identifier> <serial>
nh device certificates delete <identifier> <serial>
nh device certificates generate <identifier>
nh device certificates upload <identifier> <certificate path>
nh device certificates lookup <certificate path>
```

`generate` creates a device private key and, by default, a certificate signing request on disk, without uploading anything. Files go to `<data-dir>/certificates/<org>/`.

| Flag | Description |
| --- | --- |
| `--ca <name>` | Produce a certificate signed by a local CA made with `nh ca generate`, instead of a signing request. |
| `--self-signed` | Produce a self-signed certificate instead. |
| `--valid-for <duration>` | Validity of the certificate, for example `31y`, `90d` or `12h`. Default `31y`. |
| `--upload` | Register the signed certificate with the device after generating it. |

`lookup` finds the device, anywhere in the organization, that a PEM or DER certificate is registered to. Only the certificate is sent.

See [Device certificates](/auth/device-certificates).

### `nh device shared-secrets`

Manage a device's own shared secrets. Alias: `shared-secret`.

```bash
nh device shared-secrets list <identifier>          # the device's keys, deactivated ones included
nh device shared-secrets create <identifier>        # create a key and secret
nh device shared-secrets delete <identifier> <key>  # deactivate a key (alias: deactivate)
```

The secret is printed once by `create` and cannot be fetched again. `list` never shows secrets. See [Shared secrets](/auth/shared-secret).

## `nh firmware`

Manage a product's firmware.

```bash
nh firmware list
nh firmware show <uuid>
nh firmware upload [path]       # alias: publish
nh firmware download <uuid>
nh firmware delete <uuid>
```

`download` saves the image in the current directory as `<uuid>` with the extension for its format. Pass `-f`/`--file <path>` to choose the path, or `--file -` to write to stdout.

### `nh firmware upload`

Sign a firmware image and upload it to the product.

| Flag | Description |
| --- | --- |
| `--key <name>` | Name of a signing key made with `nh key create`. |
| `--key-file <path>` | A signing key file: an fwup private key, or an RSA PEM for ESP-IDF. |
| `--password <passphrase>` | Passphrase for an encrypted Ed25519 signing key. Used with `--key` or `--key-file`. |
| `--skip-signing` | Upload the file without signing it. |
| `--deploy <group>` | Create a release of this firmware on a deployment group once the upload succeeds. Repeatable. |
| `-y`, `--yes` | Skip the confirmation prompt shown when the firmware path is detected. |

**The path.** Inside a Nerves project you can leave out the path. `nh` then looks for a single image under `_build/<MIX_TARGET>_<MIX_ENV>/nerves/images/` and asks you to confirm it. With `--non-interactive` or without a terminal, pass the path or `--yes`.

**The format** is detected from the file's contents, not its name. Before uploading, `nh` shows the image's own metadata and refuses an image built for a different product.

| Format | File | Signed with |
| --- | --- | --- |
| `fwup` | `.fw` | `fwup`, with an Ed25519 key from `--key`, `--key-file` or `NERVES_HUB_PRIVATE_KEY` |
| `atomvm` | `.avm` | `nh` itself, with the same Ed25519 keys. An existing signature is replaced. |
| `esp-idf` | `.bin` | `espsecure.py sign_data --version 2`, with an RSA-3072 key from `--key` (`<data-dir>/keys/<org>/<name>.rsa.pem`) or `--key-file`. An image that is already signed is uploaded as it is. |
| `rauc` | `.raucb` | Nothing. Bundles are signed when they are built, and the signing flags do not apply. |

If you give no key and do not pass `--skip-signing`, the upload of an fwup or AtomVM image fails.

**Deploying.** `--deploy` creates a release with the new firmware and no archive on each named group. When `--deploy` is not given, `NERVES_HUB_DEPLOYMENT_NAME` is used if set. A failed deployment does not undo the upload: the error names the firmware UUID so you can retry with `nh deployment update`.

With `-o json`, the command prints the uploaded firmware as one JSON document on stdout, with a `deployed` list of the groups it updated.

```bash
nh firmware upload --key my_app_key --deploy qa
nh firmware upload _build/rpi4_prod/nerves/images/app.fw --deploy qa --deploy staging -o json
```

See [Firmware](/setup/firmware), [Firmware signing](/concepts/firmware-signing) and [CI and automation](/outbound/ci-cd).

## `nh archive`

Manage archives: supporting fwup files a release can deliver to devices. See [Archives](/updates/archives).

```bash
nh archive list
nh archive show <uuid>
nh archive upload <path>
nh archive download <uuid>
```

`upload` checks the archive's metadata (its `meta-version` must be a semantic version), signs it with `fwup`, and uploads it. It takes `--key`, `--key-file`, `--password` and `--skip-signing`, which work as they do for `nh firmware upload`.

`download` saves the archive as `<uuid>.fw`. Pass `-f`/`--file <path>` to choose the path, or `--file -` to write to stdout.

The API has no way to delete an archive.

## `nh deployment`

Manage deployment groups. Alias: `deployments`.

```bash
nh deployment list
nh deployment show <name>
nh deployment create <name> --firmware <uuid>
nh deployment update <name>
nh deployment delete <name>
```

### `nh deployment create` and `nh deployment update`

| Flag | Description |
| --- | --- |
| `--firmware <uuid>` | Firmware to deploy. Required for `create`. On `update`, creates a new release. |
| `--archive <uuid>` | `update` only. Archive for the new release. On its own, the new release keeps the current firmware. |
| `--required` | `update` only. Mark the new release required. |
| `--state <state>` | `on` or `off`. |
| `--version <requirement>` | Version condition, for example `">= 1.0.0"`. `""` clears it. |
| `--tag <tag>` | Tag condition. Repeatable. `""` clears it. |
| `--tag-operator <op>` | `and` (every tag, the default) or `or` (any tag). |
| `--delta-updatable` | Turn on [delta updates](/management/delta-updates). |
| `--notes <text>` | Notes describing the group. |

The server always creates a group turned off, so `create --state on` turns it on with a second request.

On `update`, a new release and setting changes go to the server as separate requests: settings and `--state off` first, then the release, then `--state on`.

### `nh deployment release`

Manage a group's releases. Alias: `releases`. See [Releases](/deployments/releases).

```bash
nh deployment release list <group>               # newest first
nh deployment release show <group> <number>
nh deployment release create <group> --firmware <uuid>
nh deployment release update <group> <number>
```

| Command | Flag | Description |
| --- | --- | --- |
| `create` | `--firmware <uuid>` | Firmware for the release. Required. |
| `create` | `--archive <uuid>` | Archive for the release. Without it, the release has no archive. |
| `create` | `--description <text>` | Short description of the release. |
| `create` | `--notes <text>` | Notes about the release. |
| `create`, `update` | `--required` | Mark the release required. On `update`, `--required=false` unmarks it. |
| `create`, `update` | `--connecting-code <code>` | Elixir the device runs when it connects. |
| `create`, `update` | `--connecting-code-file <path>` | Read the connecting code from a file. `-` reads stdin. |
| `create`, `update` | `--connecting-code-mode <mode>` | Where the release's code runs relative to the group's: `first`, `last` or `override`. The server defaults to `last`. |
| `update` | `--clear-connecting-code` | Remove the release's connecting code. |

A new release becomes the group's current release. A release's firmware, archive, description and notes cannot change once it is made.

The `release` commands need a server with the deployment release API. On a server without it they fail with a message saying to upgrade. `nh deployment update --firmware` and `nh firmware upload --deploy` work on both: they fall back to the older deployment group update request.

See [Connecting code](/deployments/connecting-code).

## `nh key`

Manage an organization's firmware signing keys. See [Firmware signing](/concepts/firmware-signing).

```bash
nh key list
nh key show <name>
nh key create <name>
nh key add <name> --public-key <file>
nh key delete <name>
```

| Command | Flag | Description |
| --- | --- | --- |
| `create` | `--scheme <scheme>` | `ed25519` (default) or `secure_boot_v2_rsa`. |
| `create` | `--password <passphrase>` | Passphrase to encrypt an `ed25519` private key. Optional. |
| `add` | `--public-key <file>` | Public key or certificate file to register. `-` reads stdin. Required. |
| `add` | `--scheme <scheme>` | `ed25519`, `secure_boot_v2_rsa` or `x509_certificate`. Detected from the file when left out. |

`create` generates a key pair locally and registers the public key. The private key stays in `<data-dir>/keys/<org>/`. `add` registers an existing public key or certificate without generating anything. `delete` removes the key from the server and keeps the local key files.

A key only verifies firmware of its own scheme.

| Firmware format | Scheme | Create or register |
| --- | --- | --- |
| fwup `.fw` and AtomVM `.avm` | `ed25519` | `nh key create <name>`, or `nh key add <name> --public-key fwup-key.pub` |
| ESP-IDF `.bin` | `secure_boot_v2_rsa` | `nh key create <name> --scheme secure_boot_v2_rsa`, or `nh key add <name> --public-key key.pem` |
| RAUC bundle | `x509_certificate` | `nh key add <name> --scheme x509_certificate --public-key cert.pem` |

## `nh ca`

Manage an organization's CA certificates. See [Device certificates](/auth/device-certificates) and [Just-in-time provisioning](/auth/just-in-time-provisioning).

```bash
nh ca generate          # generate a CA key and certificate locally
nh ca upload [name]     # register a CA certificate with the organization
nh ca list
nh ca show <serial>
nh ca delete <serial>
```

`generate` writes the key and certificate to `<data-dir>/ca/<org>/`, named by the generation time.

| Command | Flag | Description |
| --- | --- | --- |
| `generate` | `--name <name>` | Common name for the certificate. Defaults to the organization name. |
| `generate` | `--valid-for <duration>` | Validity, for example `31y` or `90d`. Default `31y`. |
| `generate` | `--upload` | Register the CA with the organization after generating it. |
| `upload` | `--cert <path>` | A CA certificate not made by `nh`. |
| `upload` | `--key <path>` | That CA's private key. Required with `--cert`. |
| `generate`, `upload` | `--description <text>` | Description recorded with the CA. On `generate`, needs `--upload`. |
| `generate`, `upload` | `--jitp-product <name>` | Product that devices signed by this CA join on first connection. Turns on just-in-time provisioning. Naming the product needs NervesHub 2.5.0 or later. |
| `generate`, `upload` | `--jitp-tag <tag>` | Tag given to devices created that way. Repeatable, or comma-separated. |
| `generate`, `upload` | `--jitp-description <text>` | Description given to devices created that way. |

Registering a CA proves ownership by signing a verification certificate with the CA's private key, so the key is needed even for a CA made elsewhere.

## `nh script`

Manage a product's support scripts. Alias: `support-script`. See [Support scripts](/management/support-scripts).

```bash
nh script list
nh script show <id>
nh script create --name <name> --text-file <path>
nh script update <id>
nh script delete <id>
```

`<id>` is the integer `nh script list` shows. `list` takes `--page` and `--page-size`.

| Flag (`create`, `update`) | Description |
| --- | --- |
| `--name <name>` | Script name. |
| `--text <body>` | Script body. |
| `--text-file <path>` | Read the body from a file. `-` reads stdin. |
| `--tags <list>` | Comma-separated tags. On `update`, an empty value clears them. |
| `--language <language>` | How the device runs the body: `elixir` (the server default) or `shell`. |

To run a script on a device, use [`nh device run-script`](#run-code-and-scripts).

## `nh webhook`

Manage an organization's webhooks. See [Webhooks](/outbound/webhooks).

```bash
nh webhook list
nh webhook show <id>
nh webhook create --url <url> --events <types>
nh webhook update <id>
nh webhook delete <id>
nh webhook regenerate-secret <id>
nh webhook test <id>
```

| Flag (`create`, `update`) | Description |
| --- | --- |
| `--url <url>` | Where events are sent. Required for `create`. |
| `--events <types>` | Event types to send. Comma-separated or repeated. Required for `create`. |
| `--products <names>` | Only send these products' events. Comma-separated or repeated. |
| `--all-products` | Send every product's events, including products added later. |
| `--description <text>` | What receives these events. |
| `--enabled` | Turn the webhook on. `--enabled=false` turns it off. Turning a webhook on clears the delivery failures recorded against it. |

`create` prints the signing secret once. NervesHub does not show it again. `regenerate-secret` replaces the secret and prints the new one once, and the old one stops working at once. Signing secrets are never listed or shown.

`test` sends a `webhook.test` event and reports how the endpoint answered. It exits non-zero when the endpoint did not accept the event.

Run `nh webhook create --help` for the event types.

## `nh iroh-endpoint`

Manage an organization's iroh endpoint ids. Alias: `iroh`.

```bash
nh iroh-endpoint list
nh iroh-endpoint register <identifier>
nh iroh-endpoint show <identifier>
nh iroh-endpoint delete <identifier>
```

| Command | Flag | Description |
| --- | --- | --- |
| `list` | `--owner <type>` | Only endpoints held by this owner type: `device`, `user` or `none`. |
| `list` | `--search <text>` | Match the start of an endpoint id, or part of a device identifier or member name. |
| `register` | `--instance <name>` | Which endpoint this is, for a device running more than one. |
| `register` | `--user-email <email>` | Attach the endpoint to this member of the organization. |
| `register` | `--detail <key>=<value>` | Metadata to record. Repeatable. |

## `nh config`

View and change saved CLI defaults. See [Configuration](/cli/configuration).

```bash
nh config get [key]            # show saved defaults, or one value

nh config unset <key>

```

## `nh status`

Check that the configured server is up. It calls the server's health check, needs no token, and exits non-zero when the server is unreachable or reports a problem.

| Flag | Description |
| --- | --- |
| `--timeout <duration>` | How long to wait for the server to answer. Default `10s`. |

## `nh migrate`

Import settings and signing keys from the Elixir `nerves_hub_cli`. See [Migrate from the Elixir CLI](/cli/installation#migrate-from-the-elixir-cli).

| Flag | Description |
| --- | --- |
| `--from <dir>` | Old CLI data directory. Defaults to `~/.nerves-hub` or `$NERVES_HUB_HOME`. |
| `--dry-run` | Show what would be imported without writing anything. |
| `--force` | Overwrite settings and keys that already exist. |

## Errors and exit codes

`nh` exits `0` on success and `1` on failure. A command interrupted with Ctrl-C exits `130`.

When the API refuses a request, `nh` prints the status code and the server's message, then one line per invalid field:

```text
api: 422: Unprocessable Entity
  conditions.version: is invalid
```
