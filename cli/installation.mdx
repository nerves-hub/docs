`nh` is the command-line interface for NervesHub and NervesCloud. It is a single binary written in Go, so it needs no Elixir toolchain. It manages organizations, products, devices, firmware, [archives](/updates/archives), [deployment groups](/setup/deployments) and [signing keys](/concepts/firmware-signing), and generates the X.509 certificates devices authenticate with.

## Install

<Tabs>
  <Tab title="Homebrew (macOS and Linux)">
    ```bash
    brew install nerves-hub/tap/nh-cli
    ```

    To upgrade later:

    ```bash
    brew upgrade nerves-hub/tap/nh-cli
    ```

    <Warning>
      The same tap carries the older Elixir CLI as `nerves-hub/tap/nh`, which installs the same `nh` command. If you have it, remove it first:

      ```bash
      brew uninstall nerves-hub/tap/nh
      ```
    </Warning>
  </Tab>

  <Tab title="Prebuilt binary">
    <Steps>
      <Step title="Download the archive">
        Download the archive for your system from the [latest release](https://github.com/nerves-hub/nh/releases/latest).

        Archives are named `nh_<version>_<os>_<arch>`. `os` is `linux`, `darwin` or `windows`. `arch` is `amd64` or `arm64`. Windows archives are `.zip`. The others are `.tar.gz`.
      </Step>

      <Step title="Extract the binary">
        Extract the archive. It contains the `nh` binary (`nh.exe` on Windows).
      </Step>

      <Step title="Put it on your PATH">
        Move the binary to a directory on your `PATH`.
      </Step>
    </Steps>
  </Tab>

  <Tab title="From source">
    Building `nh` needs Go 1.26.4 or newer.

    ```bash
    go install github.com/nerves-hub/nh@latest
    ```

    Or clone the repository and build it:

    ```bash
    git clone https://github.com/nerves-hub/nh.git
    cd nh
    go build -o nh .
    mv nh /usr/local/bin/
    ```
  </Tab>
</Tabs>

## Check the installation

Print the installed version:

```bash
nh --version
```

A release build prints the version, then the commit and build date:

```text
nh <version> (<commit>) <date>
```

List the available commands:

```bash
nh --help
```

Once you have [set the server](/cli/configuration#set-the-server), check that `nh` can reach it. This needs no sign-in.

```bash
nh status
```

## Tools nh calls

Most commands need nothing else installed. Signing depends on the firmware format.

| Task | Needs on your `PATH` |
| --- | --- |
| Sign or preview an fwup (`.fw`) image with `nh firmware upload` | [`fwup`](https://github.com/fwup-home/fwup) |
| Check and sign an archive with `nh archive upload` | [`fwup`](https://github.com/fwup-home/fwup) |
| Sign an ESP-IDF (`.bin`) image | `espsecure.py` or `espsecure`, from [esptool](https://github.com/espressif/esptool) |
| Sign an AtomVM (`.avm`) packbeam | Nothing. `nh` signs it itself. |
| Upload a RAUC (`.raucb`) bundle | Nothing. Bundles are signed when they are built. |

`fwup` is not needed when you pass `--skip-signing`. Without it, `nh firmware upload --skip-signing` warns that it cannot read the image's metadata and uploads the file as it is. `nh archive upload --skip-signing` warns and leaves the metadata check to the server.

## Migrate from the Elixir CLI

If you used the Elixir `nerves_hub_cli`, import its settings and keys:

```bash
nh migrate --dry-run   # show what would be imported
nh migrate             # import it
```

`nh migrate` reads the old CLI's data directory (`~/.nerves-hub`, or `$NERVES_HUB_HOME`) and copies into `nh`'s data directory:

- Your saved API URI, organization, product and API token.
- Your signing keys, from `keys/<org>/` in the old directory to `keys/<org>/` in the new one.

| Flag | Description |
| --- | --- |
| `--from <dir>` | Read the old CLI's data from another directory. |
| `--dry-run` | Show what would be imported without writing anything. |
| `--force` | Overwrite `nh` settings and keys that already exist. |

The old directory is only read, never changed. Signing keys are re-encoded, not decrypted, so you need no key password and password-protected keys keep theirs. Existing `nh` settings and keys are left alone unless you pass `--force`, so you can run it more than once.

After migrating, run `nh user whoami` to confirm the token still works. If it does not, sign in again with `nh user login`.
