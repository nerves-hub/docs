The `nh` CLI is a standalone binary that lets you manage your NervesHub organization, devices, firmware, and deployment groups directly from the command line or inside CI/CD pipelines — no Elixir toolchain required. Choose the installation method that fits your operating system and workflow below.

## Install Options

<Tabs>
  <Tab title="macOS (Homebrew)">
    The fastest way to install `nh` on macOS is through the official Homebrew tap. Homebrew also handles future upgrades with `brew upgrade`.

    ```bash
    brew install nerves-hub/tap/nh
    ```

    To upgrade an existing installation:

    ```bash
    brew upgrade nerves-hub/tap/nh
    ```

    <Note>
      If macOS reports that the `nh` binary is not trusted after installation, open **System Settings → Privacy & Security**, scroll to the Security section, and click **Open Anyway** next to the `nh` entry. Then re-run `nh` in your terminal.
    </Note>
  </Tab>

  <Tab title="Linux / macOS (curl)">
    Use the official install script to download and install the latest release for your platform. The script detects your OS and architecture automatically and places the `nh` binary in `/usr/local/bin`.

    ```bash
    curl --proto '=https' --tlsv1.2 -fsSL \
      https://raw.githubusercontent.com/nerves-hub/nerves_hub_cli/master/install.sh | sh
    ```

    <Warning>
      Always review install scripts before piping them to a shell. You can inspect the script at the URL above before running it.
    </Warning>

    To install to a custom directory, set the `INSTALL_DIR` environment variable before running the script:

    ```bash
    INSTALL_DIR=~/.local/bin curl --proto '=https' --tlsv1.2 -fsSL \
      https://raw.githubusercontent.com/nerves-hub/nerves_hub_cli/master/install.sh | sh
    ```
  </Tab>

  <Tab title="Windows / Prebuilt Binaries">
    Download a prebuilt binary directly from the [GitHub Releases page](https://github.com/nerves-hub/nh/releases). Each release provides archives for common platforms:

    | Platform                      | Archive                  |
    | ----------------------------- | ------------------------ |
    | Windows (amd64)               | `nh_windows_amd64.zip`   |
    | macOS (amd64)                 | `nh_darwin_amd64.tar.gz` |
    | macOS (arm64 / Apple Silicon) | `nh_darwin_arm64.tar.gz` |
    | Linux (amd64)                 | `nh_linux_amd64.tar.gz`  |
    | Linux (arm64)                 | `nh_linux_arm64.tar.gz`  |

    <Steps>
      <Step title="Download the release archive">
        Visit [https://github.com/nerves-hub/nh/releases](https://github.com/nerves-hub/nh/releases) and download the archive for your platform.
      </Step>

      <Step title="Extract the binary">
        Extract the archive to a directory of your choice, for example `C:\Tools\nh\` on Windows or `~/.local/bin/` on Linux.
      </Step>

      <Step title="Add to PATH">
        Add the directory containing the `nh` (or `nh.exe`) binary to your system `PATH` so it is accessible from any terminal.
      </Step>
    </Steps>
  </Tab>
</Tabs>

## Verify Installation

After installing, confirm that `nh` is available and check the installed version:

```bash
nh --version
```

To see top-level help and a summary of all available commands:

```bash
nh --help
```

A successful installation prints the version string, for example:

```text
nh version 0.x.y
```

## Migrating from the Legacy Mix CLI

If you previously used the `nerves_hub_cli` Hex package and `mix nerves_hub.*` tasks, run the migration command once to import your existing credentials, configuration, and signing keys into the new `nh` config format:

```bash
nh migrate
```

The migration is non-destructive — your Mix CLI configuration files are left in place. You can continue using `mix nerves_hub.*` tasks while you transition, but `nh` is the actively maintained path going forward.

## Legacy Mix CLI

The older `nerves_hub_cli` Hex package (mix tasks under `mix nerves_hub.*`) remains available for projects that have not yet migrated. Add it to your `mix.exs` dependencies if you need it:

```elixir
{:nerves_hub_cli, "~> 0.10", runtime: false}
```

New projects should use `nh` instead. It ships as a single executable with no dependency on your Elixir or Erlang installation, making it easier to use in CI and on machines without a full Nerves toolchain.
