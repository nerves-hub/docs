---

NervesHub arranges its data as a hierarchy. An **organization** contains **products**. Each product owns **devices**, **firmware**, **archives** and **deployment groups**. A deployment group delivers firmware to devices through **releases**. The entries below define each term briefly and link to the page that covers it.

## Organization and access

<Accordion title="Organization">
  The top-level tenant. Products, signing keys, CA certificates, members and integrations belong to an organization. See [Roles and permissions](/access/roles) for members and [Audit log](/access/audit-log) for the record of what they change.
</Accordion>

<Accordion title="Role">
  What a member of an organization may do. The built-in roles are **Admin**, **Manage** and **View**, from most to least privileged. From NervesHub 2.5.4 an organization can also define custom roles. See [Roles](/access/roles).
</Accordion>

<Accordion title="Product API key">
  A credential for automation that works on one product and holds a role of its own. It is on the NervesHub main branch but in no tagged release as of NervesHub 2.5.4. See [Product API keys](/api/authentication#product-api-keys) and [CI and automation](/outbound/ci-cd).
</Accordion>

<Accordion title="Webhook">
  An HTTP endpoint you run that NervesHub sends your organization's events to, as signed JSON. See [Webhooks](/outbound/webhooks).
</Accordion>

<Accordion title="Product">
  A group of devices that run the same kind of firmware, together with that firmware, its archives and its deployment groups. Every device and every firmware belongs to exactly one product. Product settings control which extensions and firmware formats the product uses, its shared secrets and its health profiles. See [Products](/setup/products).
</Accordion>

## Devices and authentication

<Accordion title="Device">
  One physical unit, known to NervesHub by its identifier, which is usually a hardware serial number. NervesHub tracks the firmware each device reports, its connection, its tags and its health. See [Devices](/setup/devices).
</Accordion>

<Accordion title="Tag">
  A label on a device. Deployment groups use tags to decide which devices they target. See [Devices](/setup/devices).
</Accordion>

<Accordion title="Shared secret">
  A key and secret a device uses to authenticate instead of a certificate. A product key is shared by every device in the product, and a device that connects with one is created on its first connection. A device key belongs to one device. Shared secrets have to be [turned on for the instance](/hosting/feature-prerequisites#shared-secret-authentication). See [Shared secrets](/auth/shared-secret).
</Accordion>

<Accordion title="Device certificate">
  An X.509 certificate that identifies one device. The device presents it during the TLS handshake (mutual TLS). Its private key stays on the device. See [Device certificates](/auth/device-certificates).
</Accordion>

<Accordion title="CA certificate">
  The certificate that signed your device certificates, also called a signer certificate. You register it with your organization and keep its private key yourself. NervesHub uses it to check a device certificate it has not seen before. See [PKI](/concepts/pki) and [Just-in-time provisioning](/auth/just-in-time-provisioning).
</Accordion>

<Accordion title="NervesKey">
  A secure element that holds a device's private key and certificates in hardware. NervesHubLink uses it automatically when the `nerves_key` library is a dependency. It holds a `:primary` certificate pair, which can be written once, and an `:aux` pair, which can be updated. See [NervesKey](/auth/nerveskey).
</Accordion>

<Accordion title="TPM">
  A Trusted Platform Module that holds a device's private key and certificate. NervesHubLink uses it automatically when the `tpm` library is a dependency. See [TPM](/auth/tpm).
</Accordion>

## Firmware

<Accordion title="Firmware">
  A firmware file uploaded to a product, with the metadata NervesHub read from it: product, version, platform, architecture and UUID. For Nerves this is a `.fw` file built by `fwup`. See [Firmware](/setup/firmware).
</Accordion>

<Accordion title="Firmware UUID">
  The identifier a firmware file carries in its own metadata. It is unique within a product. A device reports the UUID of the firmware it runs when it connects, and releases refer to firmware by UUID. See [Firmware](/setup/firmware).
</Accordion>

<Accordion title="Update tool">
  The program that applies an update on the device, and so the firmware format a product accepts. `fwup` is the default. `esp-idf`, `atomvm` and `rauc` are experimental and have to be enabled on the instance and on the product. See [Updates overview](/updates/overview).
</Accordion>

<Accordion title="Signing key">
  A key pair that proves firmware comes from you. You sign with the private key and register the public key with your organization. Devices verify firmware against the public keys they trust, set with `fwup_public_keys`. See [Firmware signing](/concepts/firmware-signing).
</Accordion>

<Accordion title="Archive">
  A signed file that a release can deliver to devices alongside firmware, for data that is not part of the firmware image. Your firmware decides whether to download it and what to do with it. See [Archives](/updates/archives).
</Accordion>

<Accordion title="Delta update">
  An update that sends the difference between the firmware a device runs and the target firmware, instead of the full file. See [Delta updates](/management/delta-updates).
</Accordion>

## Deployments

<Accordion title="Deployment group">
  The link between a set of devices and the firmware they should run. Its conditions (tags, a tag operator and a version requirement) decide which devices belong to it, and its settings control how a rollout proceeds. A group has to be turned on before it delivers updates. NervesHub places a device in a matching group when the device connects. The HTTP API and the `nh` CLI call a deployment group a `deployment`. See [Deployment groups](/setup/deployments) and [Rollout controls](/deployments/rollout-controls).
</Accordion>

<Accordion title="Release">
  One firmware version delivered by a deployment group. Pointing a group at new firmware creates a release. Releases are numbered, and the newest is the group's current release. A release can also carry an archive, notes and connecting code, and can be marked required. See [Releases](/deployments/releases).
</Accordion>

<Accordion title="Workflow">
  A definition on a deployment group that stages each release in ordered steps, for example a small first batch, an approval, then every other device. See [Deployment workflows](/concepts/deployment-workflows).
</Accordion>

<Accordion title="Update mode">
  How a device receives firmware. `automatic` means its deployment group sends updates. `device_managed` means the device asks for updates when it chooses. `off` means it receives none. See [Device-managed updates](/updates/device-managed-updates).
</Accordion>

<Accordion title="Connecting code">
  Elixir code that NervesHub sends to a device to run when it connects. It can be set on a device, a deployment group or a release. See [Connecting code](/deployments/connecting-code).
</Accordion>

## Device features

<Accordion title="Extension">
  An optional feature that a device and NervesHub agree on after the device connects, such as health, geo, logging, error reports, [local shell](/extensions/local-shell) or [network identity](/extensions/network-identity). An extension runs only when the firmware includes it and it is enabled for both the product and the device. See [Extensions overview](/extensions/overview).
</Accordion>

<Accordion title="Health profile">
  The thresholds a product uses to judge a device's reported metrics. The result is a health status of healthy, warning or unhealthy. A product has a default profile and can have one per platform. See [Health monitoring](/management/health-monitoring).
</Accordion>

<Accordion title="Support script">
  A script stored on a product that you can run on a connected device. See [Support scripts](/management/support-scripts).
</Accordion>

<Accordion title="Remote console">
  An IEx session on a connected device, opened from the web UI or the CLI. The firmware has to enable it with `remote_iex: true`. See [Remote console](/management/remote-console).
</Accordion>

<Accordion title="Product notification">
  A message NervesHub raises on a product about a problem nothing else would show, such as an extension a device could not start. See [Product notifications](/management/notifications).
</Accordion>
