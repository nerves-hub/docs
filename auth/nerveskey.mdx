[NervesKey](https://github.com/nerves-hub/nerves_key) stores a device's certificate and private key in a secure element on the I2C bus. NervesHubLink reads the certificate from the chip and uses the chip's key for the TLS handshake, so the private key is not stored on the filesystem. NervesHub sees an ordinary device certificate. Everything in [Device certificates](/auth/device-certificates) about registering the CA and adding devices applies.

## Requirements

- A provisioned NervesKey on the device. Provisioning writes the device certificate and the signer certificate to the chip. It is done with the `nerves_key` library, not with NervesHub. Follow the [nerves_key documentation](https://hexdocs.pm/nerves_key).
- The `nerves_key` library in your firmware. `nerves_hub_link` accepts `nerves_key` 0.5 and 1.x as an optional dependency.
- The signer certificate registered with your organization as a certificate authority.

## Enable it

<Steps>
  <Step title="Add the dependency">
    ```elixir
    # mix.exs
    def deps do
      [
        {:nerves_hub_link, "~> 2.14"},
        {:nerves_key, "~> 1.2"}
      ]
    end
    ```
  </Step>

  <Step title="Configure the host">
    ```elixir
    # config/target.exs
    config :nerves_hub_link,
      host: "devices.nervescloud.com"
    ```

    When `nerves_key` is in the project and you have not set `configurator`, NervesHubLink uses `NervesHubLink.Configurator.NervesKey`. It takes priority over the TPM and [shared secret](/auth/shared-secret) configurators.
  </Step>

  <Step title="Register the signer certificate">
    Register the certificate that signed the device certificates as a certificate authority. See [Register a certificate authority](/auth/device-certificates#register-a-certificate-authority). Registration needs the signer's private key, to prove you own it.
  </Step>

  <Step title="Make the devices known to NervesHub">
    Choose one:

    - Add each device before it connects, with the identifier in its certificate's common name. See [Devices](/setup/devices).
    - Give the certificate authority a just-in-time provisioning profile, so devices are created on first connection. See [Just-in-time provisioning](/auth/just-in-time-provisioning).
    - If you have a Microchip Trust&Go manifest for your secure elements, import it with `nh device import`. It creates each device with the certificate in its manifest entry.
  </Step>
</Steps>

## What the configurator does

At startup the configurator opens the I2C bus and fills in the `ssl` options that you have not already set:

| `ssl` option | Value |
| --- | --- |
| `cert` | The device certificate read from the chip. |
| `key` | A reference to the chip's private key, through the NervesKey PKCS #11 engine. |
| `cacerts` | The signer certificate read from the chip, followed by the CA certificates NervesHubLink trusts. See [Connecting devices](/setup/connecting). |

A value you set in `ssl` yourself is kept.

## Options

Set these under the `:nerves_key` key:

```elixir
config :nerves_hub_link, :nerves_key,
  i2c_bus: 0,
  certificate_pair: :aux
```

<ParamField path="i2c_bus" type="integer" default="1">
  The I2C bus number the chip is on. `1` means `i2c-1`.
</ParamField>

<ParamField path="certificate_pair" type="atom" default=":primary">
  Which certificate pair to read from the chip, `:primary` or `:aux`. The primary pair can be written once. The auxiliary pair can be updated.
</ParamField>

## Check that it works

Boot the device and open its **Settings** tab in NervesHub. The **Certificates** card lists the certificate from the chip and the CA that signed it.
